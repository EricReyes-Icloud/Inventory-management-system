# Feature: Frontend Login MVP0

**Objective:** Build the functional prototype frontend (React PWA) starting with Login screen, connecting to the existing Firebase Auth + admin middleware.

**Branch:** `frontend` (already created, currently empty)
**Delivery strategy:** ask-on-risk
**Test runner:** vitest (backend), manual/functional verification (frontend)

## Specs

- **S1 — Seed 3 admin users in Firebase Auth.** The `Usuarios/Usuarios/Admin`, `Usuarios/Usuarios/Admin_2`, `Usuarios/Usuarios/Admin_3` collections already exist in Firestore with `Email`, `Nombre`, `Rol`, `Activo`, `Telefono`. No passwords exist. We must create corresponding Firebase Auth users with secure random passwords, and add a `passwordChangeRequired` flag in Firestore so admins are forced to change on first login.
- **S2 — Backend auth login endpoint (contract revised 2026-11-23, see L4).** `POST /api/auth/login` accepts `{ idToken }` produced by the Firebase JS SDK sign-in, verifies it with `admin.auth().verifyIdToken`, checks admin membership across `Usuarios/Usuarios/{Admin,Admin_2,Admin_3}`, and returns `{ token, admin: { uid, email, nombre }, passwordChangeRequired }`. Must be rate-limited and return proper error codes for invalid or unauthorized credentials. Original wording was `{ email, password }` verified "via Firebase Admin SDK"; that is not an available Admin SDK operation and was replaced by the user's explicit choice.
- **S3 — Frontend project scaffold.** Create `frontend/` with React + Vite, PWA manifest, service worker, Firebase client SDK initialization, and a minimal routing setup.
- **S4 — Login screen.** Implement Login page matching the wireframe: email + password fields, submit button, error handling, redirect to dashboard on success. Must use Firebase JS SDK for authentication.
- **S5 — Protected route guard.** After login, routes must be guarded by checking the Firebase ID token against the backend's `adminAuth` middleware.
